A goal is not a plan. It is a durable handoff contract.

你必须非常努力，才会看起来毫不费力。

make-goal asks the missing questions, inspects the context, and writes a goal.md that future agents can execute without depending on the original chat.

Do the hard thinking before the handoff; then running the goal can feel effortless.

What goes into a real goal.md

The document captures the target, the work loop, and the checks that keep a long task from drifting.

01

Context

Final outcome, references, paths, constraints, assumptions, and non-goals.

02

Harness

Runtime, tools, dependency setup, permissions, secrets, services, and fallbacks.

03

Milestones

Phased work with acceptance criteria, quality bars, and completion definition.

04

Loop

Read progress, inspect state, implement a small increment, validate, record, continue.

Harness first, so agents do not stall later.

Many agent tasks fail after the goal is clear because the execution environment is not. make-goal makes the harness explicit before the work starts.

  • Runtimes, package managers, browsers, CLIs, MCP servers, and plugins
  • Secrets and external services documented by variable name, never by value
  • Baseline readiness checks and fallback paths when dependencies are missing
